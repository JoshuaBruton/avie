01 / The inspiration

The idea behind A.V.I.E.

I've always been fascinated by the unexplored and unexplained, particularly the possibility that satellite imagery might reveal things we've overlooked: unusual structures in remote locations, unexpected wildlife activity, or formations that deserve a closer look.

That curiosity became a practical engineering question: could I build a system that collected imagery, divided it into manageable sections, and helped me review objects of interest?

The original Python prototype explored coordinate-based image retrieval and YOLOv8 detection. AVIE has since grown into a private browser dashboard with persistent scans, configurable targets, overlapping-tile analysis, annotations, and a reviewed-example library.

The ambition is still the same: detect what may be present, then ask, does it belong there? Context-aware anomaly ranking remains a research goal.

An unusual observation is a lead for investigation. A model suggestion does not establish identity, significance, or an extraordinary explanation.
02 / System design

From coordinates to reviewable evidence

01 / DEFINE

Choose an area

Set coordinates, radius, targets, and model settings. Stonehenge is the default location.

02 / QUALIFY

Check the imagery

Import a licensed aerial capture with resolution, coverage, rights, and capture metadata.

03 / ANALYZE

Run eligible detectors

Process overlapping tiles, remove duplicate detections, and filter candidates to the scan radius.

04 / REVIEW

Save the investigation

Inspect candidates, draw regions, add notes, save assessments, and export a traceable report.

Implemented: overlapping-tile analysis across the supplied scan image, persistent history, configurable targets, and a browsable review interface. Coverage is bounded by the imported image, scan footprint, and processing limits; larger areas do not guarantee useful detail.
03 / Detection strategy

Keep each kind of evidence visible

People & wildlife

Supported animal classes, a dedicated third-party aerial human detector, and an optional aerial wildlife localizer generate experimental candidates. Marine and reptile categories currently support manual review rather than specialist automatic classification.

Structures & visual features

Building segmentation suggests roof and footprint regions. Geometry and contrast-based proposals flag unknown features and possible structure remnants. Archaeological age, human origin, and significance require further investigation.

Map context & observations

OpenStreetMap agriculture and heritage records remain separate from image findings. Manual marks preserve the reviewer's label and notes. A known mapped site is never counted as an image discovery; mapped farmland is not image-based crop classification.

Model scores, localization scores, mapped records, and human assessments retain their separate meanings. None establishes that every person, animal, or site has been found.

04 / Engineering deep dive

The hard part isn't just finding objects

Resolution before inference

Detailed analysis requires verified native aerial resolution of 5 cm per pixel or better, delivered spacing of 5 cm or better, and appropriate analysis/display rights. Upscaling cannot satisfy that requirement. Esri provides a separate context layer; detailed image detection is skipped when imagery is ineligible.

Time and provenance

Reports preserve provider/licence metadata, native resolution, delivered spacing, and capture dates separately from analysis timestamps. Historical imagery remains useful, but findings refer to the capture. Missing dates remain unavailable, and digital zoom stops at native pixel size.

A persistent review workflow

A JavaScript API manages the job queue, history, reviews, and exports in private R2 storage. An external Python worker performs inference. Linked close-up scans reuse the same baseline, preserve the parent scan, and cannot create additional source detail.

Learning from reviewed examples

Reviewers can cut native image crops, label positive and negative examples, and export a training dataset. Preparation groups nearby or related scans before validation splitting. Saving examples never retrains the engine automatically; custom AVIE human weights have not been trained or activated.

05 / Validation & lessons

Build the workflow. Test the claims.

49 automated checks passing

The documentation review on November 13, 2026 verified 20 web API/policy/place checks, 24 Python backend checks, and five original CLI checks. They cover persistence, reviews, exports, imagery eligibility, capture metadata, evidence separation, and training-data preparation.

These checks establish software behavior. They do not measure detection precision or recall in the field.

A useful experiment, with limits

In a historical Stonehenge experiment before the current imagery gate, a general person pass returned zero boxes while the dedicated aerial layer returned three possible-person boxes. Some visitors were still missed. Structure proposals also flagged the central stone cluster, separately from the known map record.

That single scene helped guide development; it did not establish reliable survey accuracy or satisfy today's imagery requirements.

The biggest lesson: an impressive-looking box is only useful when its source, date, uncertainty, and review history are clear.
06 / Project roadmap

A working foundation. More to establish.

Implemented in the repo

Private dashboard, persistent scans and reviews, tiled inference, target groups, manual annotations, close-up lineage, mapped context, capture reporting, and reviewed-crop exports.

Next practical milestone

Obtain qualifying licensed Stonehenge imagery, verify the matching frontend/API and v7 Python worker deployment, and evaluate detections on independent sites with reviewed labels.

Long-term research

Validated specialist models, broader licensed datasets, and context-aware anomaly ranking. Marine/reptile automation and subtle or buried archaeological features require further research and suitable data.

Current boundary: no qualifying Stonehenge baseline has been obtained, and no independent people/wildlife accuracy claim is established. Repository implementation and live deployment are tracked separately. Model and dataset licences also constrain reuse.
